# QA-01：20 组真实在线问答实测

已测完。托业定义恢复了可读回答，但目前还不能宣布“问答体验全部恢复、可以随意现场提问”：日期与基础材料仍有遗漏，一题给出了错误的补交说法，一题混淆了日语/英语考试，一题在线整理失败。

这是实测报告，不是修好后的宣传样张。下方保留全部原回答，包括失败；整理报告没有替模型改写回答。

## 一眼看懂结果

- 20 组场景，22 个对话轮次，加 3 次专门的缓存复问，共 **25 次应用请求**。
- **39/50 次实际模型调用**，剩余 11 次未使用；包含失败，不做自动重试。没有另请模型评分。
- **9 组达到本题目标，5 组需优化，6 组未通过**。这是按预先写出的目标人工审阅的本轮样本结论，不是统计准确率或稳定性保证。
- 25 次 HTTP 均为 200，但其中仅 **20 次在线成功、4 次缓存、1 次降级**；HTTP 200 不代表模型答对。
- 一般新请求耗时中位数 **5.28 秒**，本轮最长 **14.61 秒**（含应用处理；首题含首次加载开销），不能推算以后每次都一样快。
- 调用台账记录 input **209,034** / output **10,837** token，其中 provider 报告缓存输入 **3,584** token。未查询账单，**不虚构人民币金额**。

## 最需要修的四件事

1. **先修会误导学生的答案。** Q07 说“材料不完整可以补交”，p10 的既有资料明确出愿期间无法提交的材料会导致不受理；Q12 却能说对，说明相近问法的结果不一致。Q14 把 JLPT/J.TEST 当作“英语外部考试”的替代问题处理，应分清英语配点、日语要求和日语考试替代。
2. **把已有的日期和材料找回来。** Q05/Q06 漏掉“2026年6月1日09:00开始网上登记”；Q10 漏掉已有共通材料表中的基础项。这些信息已经在当前 KB 中，不应先下载文件、重建向量库或增加学校专用分支。
3. **回答先给结论，再给必要说明。** Q08 中文问却主要日文答；Q11 达1863字符。段落渲染改善不能替代答案内容的精简。Q03 概念问题还进行了不必要的学校资料查询。
4. **记录在线失败，不把降级算成功。** Q13 final 返回额外字段，闭合 Schema 校验拒绝；降级标识有效，但在线回答没有完成。单次失败尚不能证明系统性传输故障，更不能为通过测试直接放松校验。

## 明天怎样演示

建议用**已选目标的结构化日期/材料页面作为主线**，问答作为辅助；结构化页面未在本轮重新验收。开场说明“这是2027入学的固定历史资料演示，不是当前开放申请窗口”。

本轮表现较稳、可以挑选的原题：

1. `托业是什么` —— 简短定义，1次调用；展示不再出现内部字段长串。
2. `我想知道托业考试满分是多少。` —— 明确990分，并区分听读与口写。
3. `纸质材料6月10日截止，是不是当天晚上23:59前送到就行？如果官方没有写具体几点，请直接说没有确认。` —— 展示不捏造截止时刻。
4. `这份资料写的日期，能直接当作2028年4月入学的出愿日程用吗？` —— 展示年度边界。

**不建议把 Q05/Q06、Q07、Q10、Q13、Q14 当成现阶段成功案例。** 如果展示测试结果，应同时披露这些失败。不要用筛选过的成功题声称已经完成可靠招生咨询。这里的推荐来自一次实测，不保证现场重新生成完全相同；本轮进程已停止，缓存不会跨重启保留。现场付费调用应从剩余11次中明确安排，不能认为“已缓存”就一定不付费。

现有产品没有聊天历史传递：Q19中“那它满分多少”会要求澄清。演示提问应写完整对象；Q20给出补全上下文的范例。不在本轮悄悄新增聊天记忆。
