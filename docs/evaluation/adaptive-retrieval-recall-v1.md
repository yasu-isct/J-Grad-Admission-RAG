各問の再現率は `|正解Fact ID集合 ∩ 最終証拠Fact ID集合| / |正解Fact ID集合|`。
42問の単純平均を全体値とし、言語別にも平均する。検索しない計画
(`needs_local_lookup=false`)は空集合、再現率0として分母に残す。計画の失敗は
現行の決定的フォールバック検索を使い、失敗件数・対象IDを別掲する。
最終証拠集合はモデルに渡す直前までの集合を指し、回答品質・正答率ではない。
検索部品のRecall@10とは取得数・フィルタ・参照追加が異なるため、差分を計算しない。

## 実行設定と再現境界

  CLI自体の初期値はオフラインであり、オンラインモデルに暗黙の既定値はない。
  オンライン選択後の設定は現行コードの既定値をそのまま使う。
- planning prompt `adaptive-qa-planning-v2`、schema `1.0`。
  timeout 90秒、max_output_tokens 8000、reasoning effort `none`、store=false。
  temperature/top_p/seedは現行実装と同様に送信しない（サービス側既定値）。
- 126回のplanning呼出しのみ。外側の再試行なし。SDK内部のmax_retries=1を維持。
  各問を固定順で3巡する。失敗・不利な結果も除外しない。途中状態は再呼出しせず停止する。
- モデル応答、検証済み計画、リクエスト、時刻、設定・内容ハッシュを保存。
  原始応答は変更せず、検証済み計画とは区別する。最終生成APIは呼び出さない。
- BGE-M3 `5617a9f61b028005a4858fdac845db406aefb181`、1024次元、CPU。
  既存モデルキャッシュ・既存391件索引を読み取り専用で使用する。
  BM25＋ベクトル＋既存RRF、1検索文top_k=12/candidate_k=48、最大6検索文。

- 生質問の単一路線とadaptiveの両方で、同じ対象と同じ製品関数を使用する。
  計画はキャッシュせず毎回取得。証拠検索は保存済み計画からのみ実行する。

### 検索文の言語

生成された検索文そのものを確認し、各文を日文／中文／混合に分類する。
固有名詞・試験名の英字だけで「混合」とはしない。漢字だけで日中を特定できない文は
判別不能として明示し、推定で日文扱いしない。複数文が日中に分かれる問も混合とする。

## 制約

42問は作者が資料を見ながら作成した固定集合であり、独立した利用者標本ではない。
中国語は4問のみ。1問の再現率が0から1になるだけで平均が0.25変わるため参考値とする。
モデル出力は変動するため3巡をすべて掲載し、平均と最小～最大を併記する。
3巡の範囲は信頼区間ではない。モデルの非固定エイリアス・サービス側設定も再現限界になる。
旧正解には現行製品が排除するscope=unknownや対象系以外のFactが含まれる。
正解を削除せず、範囲フィルタによる到達可能性を別途診断する。
同じ内容の別Factが入っても正解IDと異なれば正解には数えない。
この評価から生成回答の正確さや利用者の満足度は結論できない。

### 範囲フィルタによる到達可能性（診断値）
