# 完整两校四步前端样板

用户要求完整页面，不再交付孤立的报告或关系图设计局部。本样稿属于设计资料；生产实现已由 M17 Main 按 #239 → #240 顺序完成，并分别通过 PR #243、#245 独立验收合并。本目录保留为设计参考；下一步准备演示和私塾汇报，没有新的 Ready 实施任务，QA-01 继续暂停。

## 打开与体验

在仓库或对应设计工作区运行：

```powershell
python docs/onboarding/reader-workspace-preview/server.py --port 8029
```

浏览器打开 <http://127.0.0.1:8029/app>；前台启动可按 Ctrl+C 停止。仅绑定本机，不创建公网服务。原 `reader-report-preview.html` 现为完整样稿入口。

1. 顶部两个快捷按钮用于快速填入样稿目标，也可手动操作学校下拉框。
2. 东科大：查看日期和材料 → 继续填写个人情况 → 材料选“尚未准备/已准备” → 查看准备结果 → 生成参考报告。报告可以选择关键时间、材料与待办、其他已加载要求；复制只包含当前选中内容，不含证据链或内部字段。未填准备状态不算缺失材料。
3. 东大：CBMS 三个材料主题各有“查看依据关系”按钮。默认页面没有大图；窗口内查看文件作用与箭头，再点“查看原文”。同一窗口用返回按钮回到图，关闭/Escape 回到材料卡。计划书的入学手续关联以虚线区分。
4. 手机布局沿用同一页面；关系图纵向排列。东科大问答保留原位置和输入外观，本次不启用模型；东大沿用原能力限制。

## 复用与数据边界

- `server.py` 每次直接读取仓库现有 `src/jgrad_admission_rag/service/static/advanced.html`，并提供原 `app.css/app.js/overview.js/unified-core.mjs`；不复制或重构四步页面。设计脚本仅在这个本机样稿服务注入，产品服务不会加载。
- `data.js` 保存 UI-02 已有历史响应，来源为本机 `outputs/ui02-real/final-head-cd09bd4` 的两个 ISCT base、一个 comparison、GSFS evidence 和三个条件报告；目录元数据复用 QA20 的 catalog，并收窄到已保存响应的目标。五条图关系来自既有 `material-slice-report-plan-v1.json`。
- 东科大样例为工学院/系统制御系，2026年9月或2027年4月修士。不会把该系资料改名为信息工学系。东大为 2027年4月 CBMS 修士一般选拔A日程，只有既有三个材料主题。
- `mock.js` 拦截所有 `/v1/` 请求，在浏览器中回放资料；个人材料准备状态为合成交互，非新运行规则。东大从 yes/yes、no/unknown、unknown/unknown 三份既有报告选取案例，不是重新审核任意输入。学历/语言输入只保留交互布局，样稿不计算其新结果。
- `presentation.js` 仅覆盖报告呈现和材料卡关系窗口。继续通过原核心映射校验身份/来源；不得拿样稿截图作为生产真实数据验收证据。
- 不读取 KB/向量 runtime，不加载模型，不进行付费调用，不下载 PDF。官方链接只有使用者主动点击才访问外部网站。
