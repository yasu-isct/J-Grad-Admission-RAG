## 1. 用户目标和最终效果

在原两校四步页第二步“信息一览”中，用户直接看到考试时间、考什么、用什么语言作答和配分，
无需依赖聊天助手临时整理。复用现有布局、来源窗口、学校切换和报告按钮，不做独立页面。
日期/材料仍是现有主内容，在其后、次要资格说明前加入“考试安排”一块；移动端按相同顺序纵排。

已选目标：东京科学大学／情報理工学院／情報工学系／修士／B日程；
仅本册2027年4月或2026年9月入学两个固定批次。考试发生于2026年，不根据所选入学年替换年份。
沿用当前历史资料标识；不宣称这是现在开放的报考窗口。

中文样板（审核后的实质内容；排版可沿现有样式微调）：

> **考试安排 · B日程**
>
> **专业笔试：2026年8月18日 9:30–12:00（日本时间），150分钟。**
>
> **考什么**
> - A组：微积分、线性代数、概率统计。
> - B组：数理逻辑、自动机与形式语言。
> - C组：数据结构与算法、编程。
>
> 每个科目组各出1题，共3题。专业笔试须用日语作答。
> 专业笔试900分，英语100分。英语不另设笔试，按学校规定的外部英语成绩评价；成绩单仍须按出愿要求提交。
>
> **笔试之后**（次级、可折叠）
> 8月20日17时左右起公布口述对象；口述日期为8月24日。
> 原文说明专业笔试与英语成绩上位者为口述对象，并非所有考生都参加。
>
> [查看官方原文] [查看英语证明要求]

“查看英语证明要求”定位现有英语说明，不复制一套英语规则；原文按钮复用已有窗口，正文不堆证据字段。
A/B/C是科目组，不能与招生A/B日程混淆；原文说明出题方式，不能写成“考生每组选1题”。
本项不展示A口述卡、不新增A路线、不新增历年题目链接，也不推算总分、换算成绩、合格线或受验资格。
其他已支持专业或GSFS：“本项目尚未整理考试安排。”不得说“没有笔试”或套用CS内容。

## 3. 复用与配置，不动原知识库

新增一个独立、只读、小型的 `ReviewedExamPresentation` 展示模型及版本绑定JSON配置，建议放
`src/jgrad_admission_rag/demo_config/reviewed_exam_presentation.json`。
它是已有知识的审核展示配置，不是新的权威资格规则，也不是第二个知识库/向量库。
未修改既有ReviewedReportPlan、ApplicantProfile、KB、语料注册表、页作用域清单及334/391资产。

当前真实base响应已含fact:00288（英语配分/方式），但没有fact:00289；
ReviewedReportEvidenceRecord又要求rule_ids。因此：
- 288与287优先复用已有校验结果；289从同一已注册、已校验KB只读获取。
- 不编造资格规则把289塞进原report evidence bundle，不扩充原受保护规则文件。
- 年份锚点独立标记pdf_page/context，字段映射绑定至固定PDF；没有Fact就是没有Fact。
- 复用已有corpus选择、路径解析、身份与hash校验、页码/Fact/作用域核对方法，不复制出第二套语料选择器。

服务配置增加可选 `exam_presentation_paths: tuple[Path, ...] = ()`；默认空时旧启动方式照常工作。
演示启动器为匹配本册身份的运行库选择随包配置，不向runtime目录写入副本；其他PDF不自动套用。
新增配置不得从用户请求指定路径或任意URL获取。无需新下载、依赖安装或资料导入界面。

启动时把已核验的展示配置和必要Fact保存在ServiceState；以config hash、document identity、KB/PDF hash绑定缓存。
可使用现有生命周期/缓存习惯，不引入独立缓存平台。启动可读现有KB JSON、PDF核验结果；不运行PDF解析器或BGE-M3构建。
每次请求仍复用现有目标/当前语料选择核验，再精确匹配已验证的展示记录；不得跳过版本/身份检查。
同一请求不为考试卡重复执行整套规则报告；不要重复读取/审核同一来源来给每个字段拼卡片。

配置必须包含：schema_version、presentation_id、完整source identity、精确target scope、审核来源、字段→来源映射、结构化schedule。
校验至少包括：唯一匹配；无重复source/claim ID；KB和PDF身份一致；Fact存在、全文sha/页码/scope匹配；
短引文为原Fact精确子串；中文字段的引用键全部能解析；上下文不能升级为本系事实。
题数、时长、日期/时段与已审核字段相符；未知不得用0补齐。运行配置不得接收由客户端补充的“已审核”结论。
配置或来源不匹配时关闭考试展示，不回退到相似学校/年份/向量搜索或大模型答案。

## 4. HTTP与展示字段合同

复用 `POST /v1/base-requirements`，请求JSON继续是现有DemoTargetRequest，不给目标身份模型混入展示开关。
增加可选查询参数 `include_examination_information`（bool，默认false）。
示例：`POST /v1/base-requirements?include_examination_information=true`，body仍为原学校/学位/批次/学院/系/路线对象。

未传或false：返回旧响应形状，**不新增 `examination_information: null`**，不改requirements、统计、日期/材料语义。
显式true：在旧基础要求响应旁增加 `examination_information`，不能把考试塞进原严格的材料/资格枚举。
个人对照、RAG、GSFS切片接口保持原合同。前端仅在legacy基础要求请求上携带开关，不把它写入scope key、个人Profile或问答请求。

新分组必有 `schema_version: "1.0"`、`status`、`target_identity`（原请求身份字段）和 `message_zh`。
status三值：
- `available`：匹配并已校验；还必须有presentation_id、presentation_sha256、source_identity、schedule、evidence和year_basis。
- `not_covered`：有效目标没有已配置的考试覆盖；schedule=null、evidence=[]，显示“本项目尚未整理考试安排”。
- `unavailable`：本应有配置，但配置/来源校验失败或匹配冲突；不显示旧值，提示“考试资料暂不可用，请查看官方募集要项”。
后两种状态不能返回可渲染的肯定考试字段；基础要求若本身正常，仍可展示原日期/材料。
后两种状态均不返回presentation_id、presentation_sha256、source_identity或year_basis，schedule固定null、evidence固定空数组。
`source_identity`使用审核表中的institution_id、document_id、source_pdf_sha256、source_kb_sha256四个名字；值必须来自服务端验证的配置。
原target选择不合法/语料冲突仍使用原422/409/503，不以考试not_covered掩盖基础错误。

`schedule` 固定字段（公开名字在本规格冻结，内部类名可自行选择）：

| 字段 | 类型与此次值 |
|---|---|
| route | b_schedule |
| exam_year | 2026，非intake.year |
| timezone | Asia/Tokyo |
| written_date / written_start_time / written_end_time | 2026-08-18 / 09:30 / 12:00 |
| duration_minutes | 150 |
| subject_groups | [{group:"A",subjects_zh:[...]},{group:"B",...},{group:"C",...}]，顺序固定 |
| questions_per_group / total_questions | 1 / 3，只描述出题，不描述选答 |
| answer_language | ja |
| specialist_points / english_points | 900 / 100 |
| english_assessment | external_score，无单独英语笔试 |
| oral_date | 2026-08-24；只给日期，不推算时刻 |
| oral_selection_note_zh | 专业笔试及英语成绩上位者为对象，不能推定本人获资格 |
| oral_announcement_date / oral_announcement_time | 2026-08-20 / 17:00 |
| oral_announcement_time_qualifier | around_from，用户显示“17时左右起”，不能展示成精确deadline |

`evidence`复用DemoEvidence的真实KB Fact形状（至少288、289，英语补充可用287），必须保留原文全文与原页码、机构身份；
新增中文不冒充原文。窗口默认打开对应p.52依据；多个字段可引用同一Fact而不重复平铺同一长原文。
`year_basis`与普通Fact证据分开，包含kind=`reviewed_cross_page_context`、审核说明，以及固定document/PDF hash下的p.1、p.2、p.52页引用；
p.1引用kind=pdf_page、无Fact ID。来源窗口可以补一句“年份按本册封面与考试流程核对”，并沿现有已验证PDF入口提供这些页的链接；
无可用本地PDF入口时不生成伪链接，保留已核验原文/官方来源入口与上下文说明，不新建PDF查看器。
界面正文和复制报告不显示hash、rule_id、Fact ID、字段名或这段内部校验说明。

前端收到结果后必须核验：目标身份、presentation/source身份、status与载荷形状、可用字段/引用完整性。
只收到半份available、跨目标响应或字段/来源不对应时隐藏整块肯定信息，不从旧缓存补缺。
切换学校/系/批次/路线或新请求开始时清除旧考试卡与报告状态；沿现有请求取消/快照机制防旧响应覆盖。

## 5. 报告主题与兼容

保留原报告按钮和复制机制；新增独立主题键 `exams`，中文“考试安排”。
有available数据时才提供此主题；**默认不勾选**，不改变当前日期/材料默认选择。
用户主动勾选后，预览和复制从同一已验证结构化schedule投影，不能由模型另写一份。
仅勾日期/材料/其他不夹带考试内容；仅勾考试不输出材料准备结论/个人缺项。
没有考试覆盖时不生成空壳考试报告；已经打开的报告遇目标变化失效。
不要为考试展示再发个人对照请求：仅勾考试使用已加载基础数据即可；原日期/材料个人对照按现有需要保留。
原canonical报告和现有topic语义不改；考试作为单独已验证的展示扩展传入同一reader projection，保持旧调用输出。
不要把它伪装成已有资格/材料topic，也不要为考试新建独立报告服务。

报告样板：
> 东京科学大学／信息工学系／B日程／本册历史资料
> 专业笔试：2026年8月18日9:30–12:00（日本时间，150分钟）。
> A组：微积分、线性代数、概率统计；B组：数理逻辑、自动机与形式语言；C组：数据结构与算法、编程。
> 每组各出1题，共3题；专业笔试用日语作答。专业900分、英语100分；英语按指定外部成绩评价，仍需按规定提交证明。
> 口述对象：8月20日17时左右起公布，口述日期8月24日；以学校通知为准。
