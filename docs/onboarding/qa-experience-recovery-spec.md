## 背景与用户可见目标

用户在 UI-02 预览询问“托业是什么”，看到很长的日文检索串、`fact_type`、`scope`、
`section_path` 和 Markdown 表格符号。现场 GET `/v1/generation-status` 确认 8002 是
`reviewed-state-offline / offline_rules`，不是 M10 在线体验。设计此前启动了该离线预览；
本次问题不应全部归因于新 UI 删除了 M10，也不能未经逐例核对就宣称没有回归。

[M10 #180](https://github.com/yasu-isct/J-Grad-Admission-RAG/issues/180) / PR #181 已真实验收
一般定义一次调用、学校问题最多两次、完全重复零调用缓存。当前 `service/app.py` 的 adaptive
分支仍在；`_offline_simple_qa_answer` 直接拼接前三条 `record.text`，
`_adaptive_final_fallback` 也拼接原始片段。`app.js` 把整段回答放入单个段落。
M9 #160 是权威规则和证据闭环；M10 是 reference_only 整理层，两者不能混为一谈。
UI-02 的真实报告与合成问答验证不构成真实在线问答验收。

目标：用户能看懂当前是否启用在线整理；在线时沿用已完成的 M10 能力，得到有段落和重点的回答；
离线或失败时看懂发生了什么及可用的相关原文，不把原始检索载荷当成整理答案。
对学校特定信息没有依据时明确未确认，而不是把未覆盖说成学校不接受。

## 范围与呈现合同

1. **模式可理解。** 提问前可见“在线问答已配置”或“离线：仅检索本地资料，未启用 AI 整理”等
   等义说明。离线按钮不能承诺智能生成；失败、离线、在线成功、缓存成功分别标识。
   复用现有 status/delivery 字段，不通过浏览器自动探测远端或读取密钥。状态请求失败显示未知。
2. **在线回答可读。** 保留经过现有结构验证的自然表达，不重新建立逐句白名单。
   至少正确显示段落、项目列表和常见强调；长内容可读、390px 无横向溢出。
   HTML、脚本、事件属性和危险链接不得执行。先检查已有依赖；确需解析库时说明最小成本，
   不引入 React/Chainlit 或完整前端栈。不能用 `innerHTML` 直接渲染模型内容。
3. **离线/失败不能倾倒载荷。** 先给短状态说明，把相关原文与一般说明分开。
   使用已绑定 Fact/来源中的纯文本和可读标题，不展示 embedding/search 的序列化元数据、
   内部 IDs、路径或哈希。不得靠删除任意冒号前文本、词表或句式猜测来清洗招生原文。
   若无法可靠获得纯原文，明确无法展示，不把猜测文本当来源。
   片段可默认折叠并提供展开完整可用内容；不截断条件后给出相反结论，不把多个来源强行合成规则。
   离线不新增考试百科或模板回答来伪装模型能力；“托业是什么”离线时允许明确解释能力未启用。
4. **保留失败语义。** planning 失败可沿用既有本地回退；final 失败保留已验证的一般说明并清楚
   标识没有完成最终整理。零命中不产生学校肯定/否定结论。失败或离线结果不进入成功回答缓存。
5. **复用 M10 的配置说明。** 给出从项目根目录启动当前 main 的明确离线、在线命令及正确的
   391/模型缓存路径；在线模型沿用现有支持配置。不得把 `outputs/design-...` 写成用户唯一入口。
   清楚说明 URL/端口、模式确认和如何停止自己的服务；不自动启用付费 provider、修改用户环境，
   不在截图/日志/命令中暴露密钥。配置说明不等于真实在线验收。

优先在现有兼容响应字段内处理；如必须扩展公共响应，只允许向后兼容的可选展示数据，并说明
旧客户端兼容。需要破坏性 Schema 或改变答案信任边界时先交设计判断。

## 验收矩阵

同一目标、输入与模式进行前后比较，标明真实、合成、历史证据，不能用模式变化冒充代码改善。

| 场景 | 必须证明的结果 |
| --- | --- |
| “托业是什么”及“雅思是什么”“JLPT 是什么” | 合成 planner 不要求本地确认时一次调用、无检索；可读定义；不增加三个专用分支 |
| “出願期間と書類必着日はいつですか。” | 必要时目标内检索并最多两次调用；学校事实依据不越界 |
| “托业840按官方的标准是多少英语配点，还有没有jlpt成绩，j-test可以吗” | 分清一般解释、已检索信息和未确认内容；不得编造学校换算/替代规则 |
| 无命中学校问题 | 明确本地未确认；不得把缺证据变成不接受/不需要 |
| 离线且有长片段/重复来源/日文表格 | 内部字段不外露，原文与状态分开，条件完整可查看，手机可读 |
| 离线无命中、planning 失败、final 失败 | 状态不混淆；无静默额外调用；final 一般说明与未整合片段区分 |
| 精确重复与换目标 | 成功精确重复零调用；换学校/项目/批次不复用错答案；失败不缓存 |
| HTML/脚本/危险链接与长文本 | 不执行、不造成布局溢出；合法段落/列表仍可阅读 |
| 原 v1 流程和东大选择 | 日期/材料/个人入口/报告入口布局保留；东大问答继续标明未开放 |

## 两个检查点及所需证据

一个 Issue、一个 PR，常规开发由独立开发 Agent 完成，可沿用现有开发 chat；每段只携带当前 Spec。

**检查点 1：不付费的实现与验证。** 先提交复用映射、原始模式诊断、通用缺陷归属和对应修复；
完成上述合成 API/浏览器矩阵。使用现有真实 391 资料和缓存做有界离线浏览器验证，保留改前/改后
同一问题的可读性证据；旧用户截图作为已知改前输入，不新增旧代码服务重跑。
桌面 1440 和手机 390 截图要能看清短答案、长片段、降级状态；不能只断言 DOM 存在。
记录精确 head、启动命令（无密钥）、状态响应、目标/语料身份、计数及保护文件前后身份。
此时可以申请设计检查点审查，但不称已恢复真实在线效果或请求最终合并。

**检查点 2：在线实证与独立验收。** 离线修复、定向检查与 CI 通过后，由设计向用户提供精确 head、
模型、预计场景和最大额度，再申请真实付费授权；本 Spec 当前额度为零。
建议另行申请最多 6 次 provider 调用：开发一般定义 1、日期 2、混合问题 2；设计独立定义 1。
两方各重复一次成功请求证明缓存零新增。这里是待批准方案，不是调用许可。
任何失败/重试均计数，SDK retries=0；一般定义意外走两次即记录失败，不挪用后续额度补测。
若代码因失败发生变化，需说明旧证据适用范围及新 head 所需剩余额度，不能把旧 head 结果冒充新 head。
无授权时保持 Draft，并标明“离线检查点完成，真实在线验收待授权”，可继续不依赖付费的修复。
若用户决定仅交付离线改善，须先明确缩小交付声明，不能默认视为在线恢复通过。

定向测试沿用 adaptive/natural-language API/UI、受影响 CLI/config 与 M9 boundary 测试；
Ruff/format、必要的 JS 检查、两个现有离线 gate、精确 head Quality CI 必须通过。
不因小修改本地重复跑无关全仓；CI 的既有检查不得规避。若出现已知 391 排序诊断，单列证据，
不改期望来掩盖，也不未经归属核验就称无关。

## 失败、回滚与交接

无法读取真实资产/确认目标身份时停止该部分并报告，不改权限/重建/用合成冒充真实；
配置或模型失败显示可理解状态，不兜底编造学校要求。回滚仅撤销 QA-01 的代码/展示/文档变化，
恢复原服务配置，保留现有数据、模型、索引与审核产物，不回滚 M16 四步流程。

原 Issue 保留一条可更新交接记录：角色、状态、Issue/PR、branch/head、已验证/未验证、
真实预算（含失败）、下一责任方。更新前重读。只有精确最终 head 的必需证据完成，才能转为
非 Draft Awaiting review，独立设计验收后合并。后续报告与东大普通学生任务此时仍不放行。
