# UI-02：在东科大 v1 页面上接入双校与可选报告

Implementation: [#229](https://github.com/yasu-isct/J-Grad-Admission-RAG/issues/229)。设计合并并由 #191 放行后才 Ready；M16 的唯一后续实现。

2026-09-29 用户查看 M16 实际页面后给出最新产品决定：认可两校框架，但拒绝弱化日期、材料、个人情况和准备对照的重新布局。恢复单校 v1 四步页面作为产品基底，只做必要的多校和报告适配。该决定取代 UI-01 原型的视觉与流程基线，不撤销已验收的数据/API/证据约束。

- 现有 `/app/advanced` 保留旧四步页面：`service/static/advanced.html`。不是重新凭记忆绘制页面。
- 旧 `app.js` 的 Git blob 为 `b352187661bfadeffd92551f1daac79f68639993`，`app.css` 为 `8dc6b1f9d94a25d0990494be95e299e5badc0fdc`，均与 M16 前 `5fb98c4` 一致；`overview.js` 亦无差异。
- [单校发布边界](../releases/single-school-portfolio-v1.md)、[旧桌面截图](../assets/m9-grounded-rag-1440.png)、[旧手机截图](../assets/m9-grounded-rag-390.png)为结构参考；旧截图数据只是历史样例，不能覆盖真实响应。

## 用户可见目标

用户在熟悉的四步页面完成：**选择学校与目标 → 看清日期和材料 → 可选填写个人情况 → 看清需补充、已自报准备和待确认事项**。查看要求后即可按需生成资料参考报告，不必填写个人情况或走完四步。

### 1. 选择目标

保持 v1 页头、页面宽度、四步导航、目标摘要和修改方式。在原学校下拉框增加东京大学，研究科／学院、专攻、学位、年度／批次／路线依真实能力联动；东京大学只显示已接入的 GSFS 复杂理工固定切片。不得跳到第二套参考站点。保留东京科学大学全部已有选项，不缩减为一个样例专业。

### 2. 官方要求：日期和材料是主内容

- 沿用 v1 的申请概览、关键时间时间线、材料卡片与查看官方依据按钮。两块默认展开，位于个人情况和问答之前，不将它们淹没在同权重长列表或说明文字里。
- 日期突出日期值和含义，分别保留网申开始、材料出愿期间、必着截止、建议到达等已审核区分；文字、边框和字重共同强调，不能只靠颜色。不能把建议期限升格为强制截止，也不能由浏览器自行推导新的招生日期。
- 材料名称醒目，逐项显示官方适用性、条件和原文入口。未知、需确认和条件不适用必须区分；“暂无覆盖”不得显示成“无需提交”。
- 东京大学日期未纳入当前切片，显示一句“当前资料尚未覆盖日期”；不要套用东科大时间线或虚构截止日期。材料区明确“当前已覆盖的 3 个材料主题”，不称完整清单。
- 保留 v1 主栏明显的“填写个人情况，检查还缺什么”入口及流程焦点切换。右侧小卡片不能成为唯一入口。
- 在本步骤的主操作区增加次级按钮“生成参考报告”。报告是可选导出，不能抢走日期／材料的视觉主次，也不能成为查看结果的前置条件。

### 3. 个人情况：保持 v1 主流程

在原第三步输入，不放到边栏。保留东科大全部已有个人字段及“未填写／不知道／自认为不适用／尚未取得”的含义与分组。允许留空并对照。东京大学只显示已支持的在职相关条件，不把东科大字段发给东大 API；此处无需老师／学生角色选择。

### 4. 对照后：先看下一步和缺项

- 提交后自动进入并聚焦原第四步，顶部即显示行动摘要、数量和优先事项，不让用户自己发现页面底部长列表。
- 沿用“需要补充／需学校或人工确认／已记录或可能匹配”规则分组，保留筛选和会话内处理勾选。材料行清楚并列 **官方要求、我自报的准备状态、下一步**，附官方依据。用户能区分“尚未取得”和“未填写”；不得把后者一律标红为缺材料。
- “已准备”只能表示用户自报，不等于证件有效、学校已受理或资格满足。不得新增总合格率／完整性保证，不能用绿色成功状态掩盖仍需确认的事项。
- 东京大学目前没有完整材料准备状态／缺项规则：沿用现有审核条件结果呈现“需准备／待确认／当前条件不适用”，明确只对 3 主题，不杜撰完整准备统计或复制东科大状态。若无自报准备字段，不能显示“已备齐”。
- 本步骤也可放同一个报告动作（共用逻辑）；有当前个人对照时，预览／复制含已审核对照、限制及下一步。返回修改目标或个人输入使受影响结果和报告失效。

## 技术范围与非目标

复用 v1 `advanced.html/app.js/app.css/overview.js` 的结构与行为，把已验收 UI-01 目录和报告能力适配接入它。允许有边界地提取共用函数或适配层，禁止再独立写一整套同等功能 renderer，禁止通过学校名字散布专用分支。提交旧组件 → 复用点 → 必要变更映射，不能只称“参照旧风格”。

`/app` 成为改好的 v1 主页面；`/app/reference` 继续回到主页面。`/app/advanced` 的直接访问及原高级工具保持可达，避免保留两份长期分叉的主流程。正式 `jgrad-demo`、`jgrad-serve`、wheel 打包的资源闭包都必须可用。

现有能力目录、适用性规则、日期呈现、报告 API、原文与引用、GSFS byte-bound 验证保持不变。ISCT 报告仍是经验证基础要求／个人对照的展示导出，GSFS canonical report/Markdown 仍与冻结基线一致。保留旧问答入口及 UI-01 修复的来源、覆盖范围、缺失信息和回退边界，助手仍 reference_only，东大问答继续不可用。

非目标：PDF 原文坐标高亮（用户本轮“高亮”指页面重点突出）、新学校／年度／材料覆盖、解析／索引／Schema 修改、账号、云部署、付费请求。M13 暂停，#177 关闭。`service/app.py`、规则、trust pins、gate 输入和 334/391 资产不得修改。

## 两个检查点，一个 Issue／PR

1. **复用与产品呈现**：以旧页面为基础完成可运行的合成浏览器流程，提交旧／新同场景截图（日期材料、个人情况、行动摘要、手机）和复用映射。在同一 PR 中先供设计核对；布局有歧义时先处理，不消耗真实启动额度或直接宣布完工。
2. **整合与验收**：接入实际两校与报告、完善兼容和状态隔离，合成验证通过后才进行预算内真实浏览器证据；非 Draft、明确 Awaiting review 后交独立设计验收。

设计 Agent 只负责设计与验收，常规代码由独立开发 Agent 完成。可以沿用 M16 开发 chat；一段有界任务，无并行 Ready。

## 验收与必须提供的证据

- 对照旧页面截图，日期／材料主块默认可见，主栏个人情况入口清晰，提交后焦点落到行动摘要；桌面 1440 和手机 390 像素无横向溢出、无仅靠颜色表达状态。真实长内容不能用截短来隐藏条件或未知。
- 所有两校支持选项、切校和切批次、目标／输入修改、慢响应 A→B→A、重复点击、失败重试、证据打开、报告预览与复制语义一致，浏览资料无自动报告调用。
- 人工可检查的准备对照用例：至少分别含一项自报已有、一项尚未取得、一项未知／待确认；核对分组、计数、来源、下一步与原响应，而不是只做 DOM 字符串存在断言。日期测试区分必着与建议，东大无日期不能借用东科大数据。
- 合成测试覆盖上述交互、键盘／焦点、两类报告、问答成功／零命中／回退／部分不支持、正式入口与 wheel 静态依赖。沿用必要的旧流程测试，更新因新设计变动的 UI 断言，不改规则 gold。Quality CI 必须通过。
- 每角色最终 head 真实场景：ISCT 无个人情况、有上述准备状态个人情况、另一支持批次共 3 报告；GSFS unknown/unknown、yes/yes、no/unknown 共 3 报告，对照已留存 canonical 输出。复用同一会话做桌面／手机、原文／复制与旧路径验证，保留请求计数和有代表性的真实截图。
- 精确记录代码 head、源响应、预览／复制映射、25 个现有保护文件前后 SHA／大小／mtime、累计台账、实际执行／未执行项和已知 391 排序限制。不得复用 UI-01 旧截图冒充本 head。

## 新 UI-02 预算与资产影响

旧 UI-01 4/4 启动、2/2 搜索及 M15 各额度保持关闭；此次新用户要求对应单独 UI-02 任务，不重置旧账。

| 资源 | 开发 | 独立设计审核 | 合计 |
| --- | --- | --- | --- |
| 真实服务启动（含失败重试） | 1 | 1 | 2 |
| 显式报告（含客户端导出／失败） | 6 | 6 | 12 |
| 基础／个人对照／旧详细报告 POST | 10 | 10 | 20 |
| 真实语义查询、在线模型、下载、解析、构建、资产迁移 | 0 | 0 | 0 |

GSFS report POST 计入报告行；触发的 ISCT base/comparison POST 还须计入 POST 行，不隐藏嵌套调用。每启动上限 5 分钟，每操作 60 秒，每浏览器会话 20 分钟，总服务墙钟上限 40 分钟；RSS 上限 12 GiB，可用内存至少 4 GiB，触限停止自有进程并计失败。GET 仅用于这些会话。合成验证和路径预检在真实运行前完成；失败后保留日志和剩余额度，先修复合成案例，无额度则向设计提交具体补充方案，禁止自行重跑。

本任务不重测检索质量，可以在真实审核响应的前提下用只读 identity provider 避免加载模型，必须披露该模式；不能用假报告作为真实证据。用户手动预览不自动计为审核或授权额外实验。用户 8000／8001 服务及其源工作目录正在使用，不 checkout/reset/stash 或替换它们；另建／复用确认为闲置的隔离工作区和独立端口。不得复制 PDF/KB/索引或更改 ACL。

## 失败与回滚

数据／请求失败显示当前范围内的错误，不回填旧学校结果。需改 pinned core 或规则才能呈现时，提交阻塞原因，不改 gate 迎合 UI。回滚仅撤销 UI-02 的页面和适配提交，恢复 UI-01，不动已接受的招生数据、模型、索引或报告基线。一次性在原 PR 汇总指摘，修复后对新 head 验证；实现 PR 合并前必须提供真实操作和旧版视觉对照。
