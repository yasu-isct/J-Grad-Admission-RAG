# REPORT-02：可带走的简洁报告与材料待办

Issue [#239](https://github.com/yasu-isct/J-Grad-Admission-RAG/issues/239)。状态：设计文档合并后唯一Ready；M17 Main实施。QA-01 #233 / Draft #236由用户暂停，非本任务依赖；从最新main的独立分支开始，不合入问答Draft。设计：[使用者目标及交互](reader-report-and-evidence-design.md)，[局部样稿](reader-report-preview.html)。

## 背景与用户可见目标

目前报告逐项复制技术字段、重复限制和官方引文，使用者难以快速知道申请时间、材料要求及还需要准备什么。改为能保存/转发的简洁资料整理，报告主题来自用户当前选择，主页面可选按钮生成。个人条件未填也可生成基础信息报告。

## 范围与非目标

复用unified-core.mjs的legacyReport/sliceReport、app.js报告窗口/复制及现有个人对照。遵守#191已有成果优先复用，PR先提供具体调用路径映射；不重画四步主页面或创建报告第二套入口。

1. 小型主题选择沿用当前报告入口附近或原窗口，默认当前已加载的可用主题；至少区分时间与材料，其他已有结构化主题按能力提供。主题无数据仍标明未覆盖，不生成虚构内容。未勾选主题不进入预览/复制；待办仅来自选中主题。全不选时提示选择，不能生成空报告。
2. 统一用户报告投影供预览/复制：目标、所选主题、优先待办、关键时间、材料及其准备状态、其他选中信息、简短范围说明。预览与复制逐项内容一致，可有排版差异。默认无证据链、引文、页码列表、内部字段/ID/hash、canonical原始Markdown块；后台验证仍完整。
3. 用明确字段区分“待补材料/已自报准备/待填写准备情况/待确认适用/无需提交/未覆盖”。`action_required`不能直接等于缺材料，未填不能当缺失，`recorded/possible_match`不能当学校审核通过。“我已处理”仅个人进度，不覆盖正式输入。
4. 日期区分登记开始、送达必着、建议到达；时刻缺失写一次自然说明，不显示precision/end_time；不把日期未知变成具体时刻，不将建议提前日变成强制截止。
5. 未填个人情况：基础报告可生成，写“未填写准备情况，暂不能判断还缺哪些材料”。东大只三个主题和在职条件；不显示全申请缺失总数。不新增东大材料准备输入或资格判断。
6. 保留目标/条件改变时过期报告失效、请求取消、迟到响应拒绝和复制绑定。报告内容选项改变也清除旧复制状态；若只是本地投影选择，复用同一有效响应，不重复请求服务。

非目标：问答修复/报告LLM生成/自由文本新检索/学校扩覆盖/新上传或导出PDF系统/图形库/来源关系图（后续任务）。不改生产Schema、规则状态、GSFS canonical报告、hash、后台证据校验，不删除任何现有资产。不因前端app.js变化更新无关M9指纹。

## 验收与必要证据

- 第一检查点先提交**同一已有结果**的前后预览和复制样张：无个人信息、明确尚未准备、明确已有、未知/条件不足；再完成其余实现。不要求先等待新的用户批准，但发现设计样稿与实际数据无法对应时先说明。
- ISCT真实原响应映射：未准备与未知分开；已有不等于审核通过；缺失原文不会被补成学校要求。GSFS unknown、yes/yes、明确不适用三种既有条件，文案与canonical结果逐项一致，原报告JSON/Markdown校验及规则行为不变。
- 桌面1440与手机390真实浏览器：可选按钮仍显眼，生成/主题选择/关闭/复制可用；报告首屏看到目标及待办；不出现技术字段或证据链，无横向溢出。样稿虚构数据不能当真实验收。
- 主题选择/切校/切年度/改个人条件/迟到请求不能复制旧结果；保留HTML脚本不执行与剪贴板失败手动复制路径。必要时更新原有UI-02/reference夹具，移除过时“复制必须包含引用”的展示断言，但保留后台证据断言。
- 定向运行既有unified-core、UI/reference browser、受影响材料报告测试；按diff确定范围；CI必须通过，不为纯样式另跑本地全仓。
