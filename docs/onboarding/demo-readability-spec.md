# UX-02：统一字体、用户文案、材料说明和问答展示

Issue [#250](https://github.com/yasu-isct/J-Grad-Admission-RAG/issues/250)。状态：本设计合并后唯一 Ready。依赖 UX-01 #247 已由 PR #249 验收合并。
责任方 M17 Main 实施，设计独立验收；沿用[开发方针](demo-usability-development-plan.md)。

## 背景与用户目标

用户不理解“低保证/判断边界/系统对照状态”等内部词，日文材料名缺少解释，重复模板淹没准备动作，
回答与来源混杂，标题/正文粗细混乱。目标是在原两校四步页看懂每份材料是什么、自己准备到哪里，
并清楚阅读智能回答和拿走简洁报告。保持 UX-01 的报告反馈与换学校入口。

## 范围与实施顺序

同一 Issue/PR 内两次开发自检，不再另开页面或并行任务：先整理一个完整代表场景，再覆盖其余状态。
代表场景使用现有 ISCT 真实响应，包含已准备/待准备/未知材料、报告和历史在线回答；
同时核对 GSFS 部分覆盖说明及关系入口。固定方向内无需逐项请求用户批准；改变产品意义时先交设计。

1. 统一 app.css 的字号/字重层级：正文常规，标题半粗，关键日期/动作少量加粗。中日文字体栈与控件一致，
   不下载新字体、不换框架。建议正文16px/400、辅助13–14px、卡片18px/600、分区22px/600，按现有布局校准。
2. 建立旧文案→新文案→适用位置对照，清理四步页/问答/报告重复内部词。
   不显示“低保证参考回答”、RAG、reference_only、provider或模型品牌型号；后台诊断和校验保留。
   “判断边界”只有具体待确认事项时才显示“需要确认”。保留必要的未知/部分覆盖含义，但将范围说明集中成简短中文，
   不把部分资料说成完整清单，不把每条提示重复成免责段落。
3. 材料展示：中文易懂名＋日文正式名＋一句“这是什么”＋准备状态＋必要下一步。
   默认紧凑清单，特殊条件按需展开。删除每项重复的原因/个人输入/官方适用性段落和泛化学历提醒。
   “已准备”仅记录自报；“待准备”只用于明确尚未准备；未填写显示“尚未填写准备情况”。
   官方不适用/尚待判定与个人准备状态不能合并；资格/语言门槛不混入缺材料数量。
4. 复用 material code、已审核 facts/规则及既有报告投影，增加共享的展示解释映射供页面/对照/报告使用。
   盘点当前可出现的所有材料：中文名、日文名、说明、来源定位或“通用释义”、适用身份、复用处。
   通用释义不得变成招生要求；填写方式、取得途径、原件/翻译/有效期要求须有已有资料支持。
   学校义务不从另一校推断；相同词在不同学校含义不同时按现有身份限定映射。
   未核实说明保留原名并标待说明，不生成看似确定的规则。证据不足的条目集中交设计决定，不扩抓新资料。
5. 问答区名称“智能问答”；正文显著，分段/列表、合理间距，继续安全 DOM，不把模型文本直接 innerHTML。
   移除回答下方默认堆积的来源/检索明细，保留原材料页按需原文/关系入口及后台绑定。
   缺失条件、未覆盖问题、服务失败等影响理解的信息必须简短可见；失败不能包装成成功，离线不冒充在线。
   确认当前 main renderer 与暂停 QA Draft 的区别，只复用当前已有能力；不合并/cherry-pick #236。
6. 报告沿用已验收主题选择和复制，复用材料名/解释与状态映射。关键时间清楚，日期单选不含材料准备结论，
   无个人情况不推断缺什么，未填不算缺材料；正文无证据链、内部字段或默认展开原文。

## 非目标

不改检索/提示词/在线provider/cache/语义回答质量、规则权威边界、生产Schema或M9指纹。
不承诺恢复 QA20 Draft 的问答效果。无需付费测试回答质量。QA #233/#236仍暂停。
不新增首页、CSS框架、PDF解析、模型、索引、学校覆盖、普通学生材料或账户系统；不恢复M13/MinerU。
不重做#239报告或#245关系图，不隐藏真实缺失项来换取“简洁”。

## 数据与兼容性

运行配置与334/391资产只读；解释元数据属于展示层，不能改规范报告/规则结论或覆盖审核原文。
共用映射避免页面/复制各有一套名称；未知新材料code采用保留原文的回退，不能匹配到错误学校。
保留两校4步、目标过滤、个人未知状态、迟到响应清理、报告反馈、同窗原文返回焦点、移动端可操作性。
保持8003固定回滚预览，开发仅用确认空闲工作区。原回滚标签不移动、不覆盖。

## 验收条件和必须交付证据

- 先交材料解释/文案复用表，逐项可审核；代表场景前后桌面1440/手机390截图覆盖四步结果、问答与报告。
- 普通使用者能从清单读出中文材料名、用途、准备状态和行动；无一屏同义重复模板；字体层级明确。
- 材料全范围映射完整性检查和至少已准备/明确未准备/未填写/不适用/官方待确认等区别通过；
  解释不能改变原义务、状态、时间或数量。不是只断言字符串出现。
- 相同保存响应对照规范数据不变，页面及复制内容一致；日期单选、部分GSFS范围、换校隔离、报告反馈和关系返回保持。
- 问答使用之前已保存且脱敏的真实在线回答验证段落/列表/混合语言；失败、离线和恶意HTML用合成输入，
  明确标记证据类型。不得调用真实provider证明一个CSS或文案改动。
- 复用现有浏览器与投影测试，做与改动相称的定向检查及现有CI。设计一次集中审查功能/说明语义/视觉，
  小修只验证直接受影响场景；单纯间距偏好记录待办，不反复阻塞合并。
- 用户未填写不被显示为缺材料、学校规则不变、失效结果不混用，是必须通过的门槛。

## 资源预算与回滚

保存响应回放为主要验收证据，不新增模型调用。开发/设计各至多1次必要最终真实会话（30分钟），
基础/个人POST合计每角色最多4次，GSFS报告每角色最多1次；不要求为了重复截图消耗额度。
付费/下载/解析/构建0；失败计数、历史预算不重置。无真实调用也可验收纯展示变化，但须核验输入来源及资产身份，
不能把回放标成实时。变更业务数据/服务边界超出本Spec，先交设计，不擅自扩大实验。

撤销本Issue展示代码即可回退，数据原位不动；参照[回滚说明](../checkpoints/demo-before-usability-20260930.md)
在独立工作区恢复旧预览。映射缺失回退日文原名，渲染失败提示并保留输入，不显示伪造内容。
原Issue/PR维护一条交接，写角色/状态/精确head、已完成和缺口、真实/回放证据、预算及下一责任方。
验收后停止功能扩展，设计准备私塾演示和汇报；不自动开始东大普通学生覆盖。
