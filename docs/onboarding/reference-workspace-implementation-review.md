## Checkpoint 1: service binding and API

The optional `--reference-workspace-config` is server owned. The closed JSON example is [reference-workspace-config.example.json](reference-workspace-config.example.json); copy it to an ignored local file and replace every `D:/ABSOLUTE/PROJECT` placeholder with a canonical absolute path. Without the flag, the old launcher and endpoints keep their existing behavior. The example binds only the accepted plan/trust/policy/seed, original five-file candidate root and original source PDF directory; it contains no copied source assets. A configured slice is pinned and audited once at startup, within the 256 KiB metadata and 64 MiB per-slice/128 MiB total source caps. The process retains immutable raw bytes plus a private canonical evidence presentation. Its snapshot ID hashes canonical plan/policy/seed/candidate/PDF content identities, independent of paths, names or time. New GETs read no source files, and each explicit report POST calls the accepted public byte-bound assembler using the captured inputs. Old provider readiness and optional slice readiness are independent. The public `service.create_app` wraps the original app factory with additive routes and a bounded optional lifespan; `service/app.py` remains byte-for-byte unchanged because it is pinned by the existing grounded-RAG implementation gate. The demo launcher uses that public factory, while the default legacy startup path adds no source audit.

The additive routes are `GET /v1/reference-targets`, `GET /v1/reference-slices/{slice_id}/evidence`, and `POST /v1/reference-slices/{slice_id}/reports`. Closed versioned response contracts expose real capability kinds, full target and snapshot identity, all required reviewed fragments/contexts and the unchanged inner accepted report plus deterministic Markdown. The POST accepts only a closed `MaterialConditionRequest`; the client cannot submit paths, pins, evidence, output or a model. Invalid schema is 422, unknown ID 404, invalid optional configuration 503, and concurrent report work 429. Responses are bounded and new page/assets carry no-store, CSP, no-referrer and nosniff headers.

Synthetic fixture tests cover valid and invalid config, bad pins, missing files, duplicate IDs, metadata cap, wrong target and conflicting profile, request extras, startup failure isolation, a second institution, stable source snapshot after disk mutation, one source read at startup, and no source reread for GET/POST. They use a one-page two-Fact synthetic PDF/candidate, not the accepted real sources.

### Design P2 follow-up: delayed evidence GET

Independent review of head `8eaab3f18ce8c0d89d5d14a5d4adfaddd5020251` found that condition edits and report generation incremented the same token used to validate an in-flight evidence GET. A valid response for the unchanged slice was silently discarded, leaving evidence hidden and the loading status stuck. The #223 review comment contains a synthetic Edge reproduction; it was not a real-source run.

The repair in `service/static/reference.js` separates evidence-selection lifetime from report/condition lifetime. Only a target change increments the evidence token and aborts its request; condition edits and explicit report generation invalidate only report state. An evidence response must still match the current request/controller, selected entry and snapshot. A current-slice snapshot mismatch or fetch failure now ends loading with an unavailable status. The old report-generation token continues to reject late reports. No API, source binding, report content, protected asset or legacy app code changed.

Browser-executed synthetic regressions delay the evidence GET while (1) editing employment, with **zero report POSTs**, and (2) explicitly generating a report, with **one report POST**. Both assert the delayed quotation becomes visible and loading ends. A separate A→B→A test verifies that old evidence responses do not overwrite the current selection and that a current snapshot mismatch shows an error.
