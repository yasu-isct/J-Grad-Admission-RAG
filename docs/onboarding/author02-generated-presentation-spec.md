## 背景和用户可见目标

用户希望沿“Agent整理核心信息和来源，再由已有程序执行”继续，并询问如何减少重复配置。AUTHOR-01已证明接入可行，但同一指南在authoring JSON和 `unified-core.mjs` 各维护一份；目标/snapshot和14原文片段还手抄进JS；`app.js`中的准备控件及摘要直接写小论文ID/名称。每加材料再复制这些分支不可持续。

本包以同一个已验收小论文完成内部整理：页面、指南、原文窗口、准备状态、报告复制保持一致；编辑已审整理输入后由生成命令同步展示，开发不再手改小论文专用JS数据/控件。不是重画页面或增加材料。

## 设计决定与范围

采用**构建时生成的受约束展示目录 + 原有通用渲染**。复用现有JSON、来源绑定、候选和报告引擎；不建CMS、图数据库、学校插件框架或在线LLM抽取器。

1. 以已验收 `author01-essay-authoring-input.json` 的 `guide`、claims和topic/material ID为中文指南源，以v2 seed的原文/上下文及已验收plan/policy/trust为事实和条件边界。保留原文件，不能为了省配置修改已验收源、生产pin或候选。
2. 一个小的构建描述只声明输入文件引用、输出schema/version及 `preparation_control=self_report_tri_state`。学校/年度/批次/快照/原文/中文步骤不得再手填一套；身份和绑定由已有输入/loader派生。程序理解这一个已用控件类型；未来新型字段需另定合同。
3. 生成命令输出静态数据模块（建议 `.mjs`，数据通过JSON安全序列化，仅固定export包装），供现有 `unified-core.mjs` 导入。给生成文件加“generated，不手改”说明、输入hash manifest和只读 `--check`；临时目录连续两次生成字节相同。展示数据不得包含可执行表达式、HTML、动态import路径或URL代码。
4. 必要时在现有 `reference_app.py` 增加**一个固定文件**的同源静态路由，沿用当前CSP与静态资产流程；禁止任意文件路径端点。更新包资源声明和实际服务测试，不能只让源码运行而打包缺失。无需改变 `/v1/reference-*` 必填字段或冻结 `service/app.py`。
5. 前端用共同函数按完整目标、snapshot、topic及绑定来源匹配目录，再给现有materialGuide/卡片/原文说明/readerReport供数据；移除AUTHOR-01小论文的手写身份、指南和原文常量。旧ISCT及旧GSFS目录本包保持原兼容路径，不一次迁移所有学校。
6. 准备控件根据已校验的topic展示描述循环生成；摘要显示真实材料名称，不硬编码“申请小论文”。仅一个已审小论文在真实目录中启用自报；不能自动给旧三主题新增控件。保留unknown/available/not_yet、修改/重新核对/缓存失效/跨学校清空和自报不改变官方结论的既有行为。

## 输入归属和字段对应

“只维护一次”是每类信息有唯一作者来源，不是把全部规则与原文混成一个文件。

| 内容 | 作者/来源 | 程序派生与消费者 |
| --- | --- | --- |
| 原文、页码、栏目和跨文件关系 | 已审v2 seed，原PDF身份不变 | 既有导入/plan；生成目录引用完整required context，不让作者再抄原文进JS |
| 学校、研究科、专攻、年度、批次、路线、快照 | seed/plan和现有reference loader | 自动派生匹配键；与服务真实evidence一致 |
| topic/material ID与中日名称 | 已审authoring claims、plan一致性检查 | 卡片、准备控件标签、个人摘要、报告显示；别名映射也由输入派生 |
| “是什么”、准备步骤、注意事项 | authoring `guide.what/preparation/attention` | 生成 `purpose/steps/warnings`；页面/原文说明/报告共用 |
| 对应事实的来源引用 | authoring claims中的fragment_ids + seed完整context | 每个显示字段映射到已审claim；缺引用/不存在片段/身份不符拒绝生成 |
| 需不需要提交、就业条件和结果说明 | 既有policy/plan | 继续由现有服务器判断，不从中文指南反推规则 |
| 是否已准备 | 用户本页自报 | 通用三态控件及现有报告投影；没有学校依据也不能冒充官方结论 |
| hash、Fact绑定、目录版本 | 程序 | 从真实输入计算、可重放；hash匹配不等于内容审核通过 |

来源锚定不要求用NLP证明中文翻译正确。生成器验证引用存在、完整上下文和身份；设计仍审核中文语义。若现有输入缺乏逐指南字段引用，可新增只包含**字段路径→已有claim ID/字段**的映射描述，禁止复制中文或原文正文。`preparation_status`为产品说明，可标明self_report无官方fragment；不得把该例外扩为官方要求。

本轮**不重写或重签policy/plan**。它们的精确字节与snapshot保持不变，既有配置生成器留作历史重放。plan的条件结果说明和指南的“怎么准备”职责不同，不能机械合并；需消除的是同一指南在前端的人工副本。后续是否把更多plan说明从claim组合生成，另凭实际重复成本决定。

## 身份与失败处理

- 构建时使用现有完整loader核对seed/policy/plan/trust/候选，不提供“绕过校验生成”。引用只读既有候选，禁止调用publish构建新候选。
- 运行时仍校验完整target+snapshot、材料ID、来源record/source/page/role/stage与所需全部片段。当前14片段的防错能力不得退化为只认topic ID或学校名。生成数据可以带派生的原文匹配信息；这是机器产物，不能再靠人同步。
- 原网页对不匹配/缺上下文的拒绝行为保留；不能在未知目标套用小论文中文解释。旧配置3主题、新配置4主题保持。
- 新静态模块失配/格式错误应不输出错误指南；缺文件或加载失败要给可理解的加载提示/重试，不留下无限loading。不新增学校专用降级逻辑。
- 作者输入有变动，manifest/check必须检测。生成新文件本身不授予新招生内容可信状态；只有PR审核通过的输入和产物可随程序发布。此次生成的trust含义不得扩展为自动事实审核。
- 文件路径只属本机启动配置，不参与资料身份；在设计/开发两工作区用相同输入应得到同一展示数据，避免绝对路径导致无意义产物变化。

## 非目标与兼容性

不新增问卷或其他真实主题，不增加学生全覆盖，不下载模板，不做年度更新器/任意规则DSL/用户上传配置；不改问答、规则资格边界、报告布局或审查文案。用户现在看到的内容和规则状态应保持，不借内部整理再次美化界面。

不改生产Schema必填项，不改M9跟踪文件或gate/pin；确有必要时结包给精确差异，不能自行重签。原334冻结、391 runtime、旧GSFS候选与AUTHOR-01 `7ea490...`候选、原PDF、旧v1/v2配置都只读。线上服务/工作区不切换。源文件和证据引用在生成产物中可以重复，**无需追求只保存一份字节；目标是只人工维护一处**。

## 验收：一次交可审成果包

1. 完整生成器、输入描述、生成目录/manifest、字段映射和 `--check`，可在空临时输出目录重现。已有 AUTHOR-01 输入/plan/policy/seed/信任/候选逐字不变。
2. 卡片/指南/原文窗口/准备摘要/报告在桌面与手机保持原语义与复制内容；已准备/未准备/未知、改就业后重查、换学校清空、返回焦点正常。新4主题、旧3主题和ISCT考试报告均有相称验证。
3. 在**隔离合成测试**中修改一个准备步骤，仅改一个authoring字段即可同步页面与报告；篡改生成文件而不改输入须被 `--check` 检出。不能为演示同步而修改真实已审内容或资料pin。
4. 再用一个完全合成的不同学校/目标/主题/片段和显示名测试同一渲染及控件，无须在JS追加该学校/材料分支；清楚标注synthetic，不作为真实学校可用性证据。这用于证明没有换地方继续硬编码，不授权新真实主题。
5. 错学校/年份/路线/批次/snapshot/缺表头/缺片段、重复topic、输入/产物hash失配均有负例；未知字数/截止时刻不自动填充。旧API请求及报告判定保持。
6. 独立服务确认生成静态模块可GET、实际新候选目录响应可消费和个人报告成功；其余交互/旧功能优先保存响应回放。不能只做合成UI且未验证实际静态路由。打包资源有检查，禁止触发安装下载。
7. 提交“改前要人工改哪些位置→改后改哪里”的对照，以及一次合成新增记录的修改文件清单。记录实际耗时/返工，未计时写未知；不得宣称已自动审核、可直接全校扩展或节省比例。

测试针对生成/身份、控件和静态路由；常规CI照常，不重跑embedding/PDF全解析/在线问答。定向测试需包含独立语义预期和变异负例，不能让生成器同时生成全部expected以自证正确。

## 资源预算、回滚和交接

本包为独立展示配置任务，不重置AUTHOR-01/IMPORT/EXAM旧额度。开发最多真实offline服务1次、产品POST4次（含失败）；设计预留服务1次、POST2次。GET、必要保存响应回放和只读校验按需，记录累计；修小UI不重复启动。只用本地既有依赖/模型资产，不主动问答。

新候选/KB/向量构建0、下载0、付费0、解析流水线0。小型静态生成/manifest允许，在新输出路径写入，不覆盖冻结资产；每次生成60秒以内，生成产物总计1MiB以内，若超过先检查重复内容，不无控制扩大。
