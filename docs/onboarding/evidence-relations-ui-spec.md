# EVID-UI-01：多文件依据关系与按需原文弹窗

Issue [#240](https://github.com/yasu-isct/J-Grad-Admission-RAG/issues/240)。状态：本次收尾文档合并后唯一 Ready；前置 REPORT-02 [#239](https://github.com/yasu-isct/J-Grad-Admission-RAG/issues/239) 已由 PR #243 验收合并（37603cf7292f573eaf9f802421a0ea82fe22725f）。M17 Main 从最新main实施，保留已验收简洁报告；不依赖恢复QA-01，不并行修改app.js。

## 背景、目标和复用

使用者看到同一材料后列了三个来源按钮，很难理解为什么需要三份文件。用户进一步明确：关系图自然融入现有两校四步页面的“英语成绩单”等小卡片，主页面只保留短结论和按钮。**关系图本身也在可关闭的模态窗口中显示，不在正文展开大图，不新增独立页面/路由/顶级导航。** 简洁报告保持无证据链。

复用`material_slice_report.py`校验后的`ReviewedMaterialSliceEvidence.relations`与records、`reference_workspace.py`的同一snapshot响应、`unified-core.mjs`映射、`app.js::openDemoEvidence`及现有模态原文查看器。现有plan已审核5条关系；不让LLM生成关系，不建立图数据库、PDF解析器或新前端框架。设计示意见[阅读体验设计](reader-report-and-evidence-design.md)。

## 范围与兼容要求

1. 在现有四步页面中每个适用材料卡内放“查看依据关系（N份文件）”按钮，点击打开模态窗口显示关系图。默认页面不渲染占位大图，打开/关闭不改变材料列表高度、滚动位置或个人输入；不另建页面、路由或导航。文件节点显示简称、相关页、中文作用。结论沿用当前有效结果，无个人条件时不得偷调用报告或伪造已判定状态。
2. 后端公开证据DTO当前没有relations。只允许为已有GET增加默认空的可选展示关系字段，复用同次已验证bundle，不改变canonical报告、plan/trust/hash、规则或生产Schema。字段绑定同一snapshot/revision，from/to必须是本次可见记录；客户端兼容字段缺失，缺失就显示独立卡片而非猜边。检查现有调用方兼容，不静默破坏严格客户端；若确需不兼容修改交设计处理。
3. 箭头方向与审核关系一致，显示中文意义。直接依据/关联上下文/入学手续相关分别标记。`shares_employment_context_but_separate_enrollment_stage`显示虚线和阶段提示，不能画成出愿必交关系。未知relation kind保留来源卡并说明关系未展示，不编故事。
4. E03→E01→E02示例实际是送付参照→按专攻确认→专攻直接条款，绝非三份文件都要求提交英语成绩单。E04→E05是参照检查表与提交表本身不同；E08→E06补充条件与上传方式。逐条给出可审查映射表。
5. 同文件可分组，但保留不同条款/页/阶段，不因三份文件常见就固定三节点。图中“查看原文”在**同一模态窗口内切换为原文详情**，复用现有查看器的原文/页码/官方链接能力；“返回依据关系”回到图并恢复触发节点焦点和图内滚动。不套第二层弹窗，不以新标签页承载关系图或原文片段；主动打开官方PDF保留既有安全链接。
6. 窗口始终有关闭按钮，Escape直接关闭整个窗口并返回主页面卡片按钮，背景主页面位置/输入保持；返回关系图必须用明确返回按钮。手机在同一自适应窗口内纵向排列，内容内部滚动、不横向溢出。图不得依赖颜色单独表达含义。切学校/版本/主题时关闭并作废旧图与原文，焦点仅返回仍有效的按钮，迟到GET不能污染新目标。

非目标：新募集要项/新规则/完整东大学生清单/高亮坐标/MinerU/报告改版/付费模型/知识图谱平台。ISCT已有原文查看和报告入口兼容，底层authority不变。
