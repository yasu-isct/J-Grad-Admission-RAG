# TOOLS-01：整理高级工具入口

状态：Blocked，等待 PREP-02 验收合并及设计明确放行。属于 M17，实施方 M17 Main。

## 背景与目标

普通用户需要学校、项目、资料版本、材料与日期，不需要调试检索或填写全部底层字段。
在原四步页面移除“高级工具”大面板；保留正常的两校选择、资料身份提示、英语/毕业/提交输入、报告与问答。
本任务是现有页面清理，不重新画一套网页，也不删除后台业务能力。

## 依赖审计与范围

main cd4064实际路由：reference_app.py 的 /app 与 /app/advanced 均返回 static/advanced.html，
/app/reference 重定向 /app。app.js 在启动时为旧检索和大表单绑定DOM，并无条件调用 loadCatalog；
只删除HTML会造成空节点错误。不得编辑旧 app.html 后宣称改了当前网页。

实施前提交简短“旧控件→用途→移除/保留→依赖函数/API”表，完成以下处置：

| 现有能力 | 处置 |
|---|---|
| 学校、研究科/项目、入学时间与已支持资料身份 | 保留原四步选择；当前只有一个版本时显示资料说明，不造不可用版本下拉 |
| 英语证明、材料中文说明、毕业/寄送提醒 | 保留 PREP-01/02 主流程入口 |
| 原文/关系窗口、可选报告、自由问答 | 保留当前实际行为与数据依赖 |
| 旧关键词/向量调试、trace与底层报告大表单 | 从用户页面移除入口和只服务旧控件的初始化/事件；不能用隐形DOM维持脆弱依赖 |
| 签证/灾害/奖学金等低频底层字段 | 本任务不迁移到主页面；后台API/规则保留，不误称覆盖已删 |
| 将来多版本切换 | 保留既有身份与选择合同，本任务不增加版本管理器或伪造第二个版本 |

对 /app/advanced 保持兼容访问四步页或重定向 /app；不另建管理员页面或权限系统。
拆分旧DOM依赖时保持问答、catalog及共享busy/error逻辑。仅移除确认不再使用的请求；
主流程仍需的catalog数据不得为了“减少请求”删掉。GSFS不支持能力按现有边界显示。
无需修改生产Schema、PDF、KB、索引、审核规则或问答检索流程。

3. 问答使用假provider或保存响应验证提交/显示/错误/缓存UI，不付费验收模型回答。
4. /app、/app/advanced、/app/reference兼容；旧后台端点合同保持，初始化不依赖已删除DOM。
5. 提交依赖清单、前后截图、网络/控制台记录、定向测试、精确head CI与资产hash；不以截图代替功能验证。

保存响应重放优先，付费/真实问答/下载/解析/KB或索引构建0。预算累计，不为小修重启服务。
