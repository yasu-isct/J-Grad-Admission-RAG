## 背景与用户可见目标

用户批准沿用三个设计样本继续推进。现有 `Bundle`、`MaterialConditionPolicy`、`MaterialSlicePlan` 的记录/主题集合已支持扩展，不能把它们误说成只支持三项的新引擎需求。实际限制包括页面中的“三个主题”文案、按旧 snapshot 绑定的材料解释，以及新资料尚未通过导入/报告配置接入。

本轮只增加 **申请小论文（小論文）**，不顺带接入上一轮问卷。用同一套字段整理、现有证据导入、条件/报告和原两校四步页面，完成一次真实小材料接入。用户最终能在独立候选预览中查看小论文中文准备说明、打开两份原文、复制含该项的参考报告。其他三个东大主题仍正常，东科大18系考试/材料功能不变。

目标固定为东京大学／新领域创成／複雑理工学／2027年度修士／一般选拔普通路线／A日程／2027年4月入学。历史切片，不声称当前开放。新包仅通过独立启动配置 opt-in；原在线8000及原三主题配置不切换。

## 中文内容和字段合同

这是描述已审招生资料的authoring记录，不是动态代码或新规则DSL。开发提交一个可重放的整理输入与从字段到已有配置的映射；优先使用前三例中的字段语义。只增加支持本项所需的最小适配，不做通用框架。

| 字段 | 值/要求 | 必须绑定的片段 |
|---|---|---|
| topic_id / material_code | application-essay / application_essay；稳定ID，不按中文匹配 | 新配置与目标身份绑定 |
| 中文/日文名 | 申请小论文 / 小論文 | E09-6 |
| 面向人群 | 本固定目标范围内全员；不是“全东大” | E09-1、2、8及E10-1 |
| stage | application | E09-3 |
| 提交方式 | 出愿期间网上出愿系统上传PDF | E09-3、4及E10-3 |
| 使用格式 | 专攻网站指定格式 | E10-3 |
| 书写语言 | 日语或英语 | E09-9、E10-3 |
| 内容A | 希望研究的主题及感兴趣的理由 | E10-4 |
| 内容B | 结合学习、研究或课外经历，具体说明能用于修士学习研究的自身优势 | E10-5 |

| 准备情况 | 个人自报，与“官方需要提交”分开；不增加评分或资格结论 | 复用现有准备状态表示 |
| 文件关系 | E09 supplements E10：提交对象/方式与写作要求互补 | 两条完整记录 |

页面建议文案：

> **申请小论文**
>
> 本范围内申请人需要提交。请使用专攻网站指定格式，以日语或英语准备两部分内容：①想研究什么、为什么感兴趣；②结合过往学习、研究或课外经历，说明自己的优势。出愿期间将PDF上传到网上出愿系统。
>
> 字数和版式以指定模板为准；本次资料未包含模板细目。

不得写成“入学考试现场作文”“研究计划书可以替代”“英语小论文免试”，不得从邻接在职行复制条件。不要展开本页笔试/口述内容。原文依据默认收起，沿用已存在的关系窗口和返回焦点行为。

## 复用路线和实施范围

1. **整理输入**：Agent把已审片段整理为结构化claims、中文说明、unknowns和关系；提交每个可见字段的来源映射。已有14片段是设计提供的输入，开发仍须记录其来源准备成本；本轮不是PDF从零盲抽取。
2. **导入**：复用 `reviewed_source_evidence.py` 和 `reviewed_fragment_import.py` / reviewed-source-v1，把v2输入生成新的不可变小候选。原共通2、专攻12+5、附表9+9，预期三文档Fact/Unit为2/17/18，总37。保留原文、身份和lineage。复用相同新build，不按worktree再建一份。
3. **条件与报告**：复用 `material_conditions.py` 和 `material_slice_report.py`；新policy/plan/trust文件绑定新候选。旧三主题的业务含义、原文及关系保持，依赖新KB的hash须全部重新计算，不能混用旧候选manifest。空谓词表达本范围全员，不新增学生类型字段。
4. **服务/页面**：独立 reference-workspace 配置引用新文件；原目标仍是东大同一目标，不伪造学校或新招生路线。沿用既有 `/app/advanced`、reference API、材料卡、依据窗口、报告预览/复制。正常配置仍显示3主题，新配置显示4主题，计数按实际数据生成；未知状态文案不得声称“完整清单”。
5. **中文展示**：由固定身份约束的整理数据/现有配置投影生成说明；不在UI读取任意JSON当权威规则。旧snapshot材料解释继续有效，新snapshot必须独立匹配；不以学校名或material_code单独匹配。可增加通用“补充说明”关系标签，但不复制一套东大专用渲染器。
6. **成果账本**：报告实际代码改动位置、复用位置、手填/重复字段、适配障碍、整理/映射/验证/返工耗时。给出“沿用/小幅调整/暂不推广”的结论，不以测试数或代码行数代替质量/提效判断。

## 数据、信任与兼容性

生产 Schema、已发布请求/响应必填项不作不兼容变化。确有展示扩展时仅可选新增字段并验证旧客户端/旧配置行为；不能要求所有旧调用补新字段。候选authoring格式不冒充已发布生产schema。

新seed pin由本设计给出；允许生成**全新路径**的候选import trust、policy trust、plan trust和preview config，限本目标、本来源、上述语义及production_enabled=false。它们是本次开发交付物，独立设计验收前不进入用户正在运行的服务。保留设计来源审核与开发实现自检的不同角色，不能把开发自检写成设计验收通过。

严禁更新已有v1信任文件、334冻结、391运行资产、旧东大候选f1721e7...、原语料选择指针或原preview配置。新小候选属于新摘录revision产生的合理派生文件，不是向量库副本；本轮零embedding、零向量索引、零新下载。

M9等冻结指纹不在本任务预授权更新范围；优先复用模块避免改跟踪文件。若确需改变，完成全包时一次给出精确差异、拟议指纹和仅指纹失败的证明，交设计处理，不改旧baseline或降低阈值，不为中间小修改反复请求用户转发。

## 非目标

不扩为完整普通学生清单；不接入问卷/全部日期/资格或其他专攻；不下载小论文模板、不替申请人写作/评分；不做在线抽取API、自由问答修复、MinerU/解析器替换、图数据库、自动年度更新器、学校插件系统、RAG架构重写或M13部署。保留reference_only边界。

## 验收与必须交付的证据

- 作者输入、字段/来源表、新候选路径/hash、lineage及全部新配置；新37片段逐字映射，E09上传栏目和同一行全员不可丢；旧23片段/5关系语义不变。
- 实际小论文中文卡/原文窗口/可选报告与复制文本，桌面及手机各一组；不接受仅静态HTML或合成接口冒充完整接入。四步主体和旧三主题仍正常。
- 一次真实候选生成并证明同身份复用；hash失配/缺片段/错学校、年份、路线不得输出肯定提交结论。常规准备状态和材料要求不混淆，未知字数不补造。
- 新配置实际GET/POST验证4主题和报告；旧配置3主题及旧英语/在职逻辑定向回归可优先复用已保存真实响应。至少一份东科大含考试的报告回放不受影响。
- 针对改动的导入、条件/报告、前端身份/主题计数及复制测试，正常CI；不重跑无关PDF/embedding/在线问答实验。真实响应与回放分开记录。
- 有源文件变更时，受影响claim/报告必须拒绝继续使用旧身份，或要求重新审核；可用小合成篡改负例证明，不能修改真实PDF来测试。
- 复用/成本表按整理、映射、导入、页面、验证、返工列实际开始/结束/运行与等待时间；未知写未知，不按聊天轮数估工时。前一套流程没有同任务计时，所以只报本次绝对成本和障碍，不宣称节省百分比。
- `complete / partial / blocked` 完成与缺口一页说明、原PR交接、精确head/checks、累计预算。若无CI以Spec规定的本地证据为准；若无法核验真实来源/候选则不可批准。

## 资源预算与失败处理

这是用户在2026-10-03批准的**新输入、新材料试验**；IMPORT-01旧4/4已用完、EXAM-02旧账本继续冻结，不把新任务当旧实验重试额度。

| 项目 | 开发上限 | 设计预留/规则 |
|---|---|---|
| 新候选发布 | 1个新build身份；最多8MiB | 只读审核；若来源或mapper确需修正产生第二身份，先交设计，不自动反复建 |
| 同身份复用/验证 | 可做必要只读检查，记录运行次数和耗时 | 不新增物理副本；单次候选操作60秒，候选相关累计10分钟，1GiB RSS |
| 独立真实服务 | 最多2次启动 | 1次；已有8000不得停止、checkout或改配置 |
| 产品POST | 最多16次，含失败 | 8次；开发先用一次必要闭环，其余修复优先保存响应回放 |
| 付费API、下载、全PDF解析流水线、向量构建 | 0 | 0 |

候选导入是对审核小片段的Fact/KB序列化；不经过legacy PDF builder，不复制PDF/模型/大索引。原PDF页图可以只读查看/必要渲染。服务以offline生成配置运行，只使用本地已缓存模型；不代发在线问答。

遇到常规页面或测试问题，同一任务内修复并记录；不逐条回交用户。预算即将不足时先复用证据，不能自行扩额。实际新来源歧义或不兼容schema、破坏性资产操作、不可验证来源才停止依赖动作并一次列出阻塞。预期无法实现时如实交partial，不用新引擎掩盖。

回滚：新配置不激活则既有服务没有变化；候选预览停止仅限自己的PID。代码可审查后revert；保留新候选供审计，不删旧资产。合并实现/切换用户页面必须在设计独立验收后分别记录。
