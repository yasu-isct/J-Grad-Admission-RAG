# UI-02 检查点 1：旧四步页面复用与合成呈现

本记录供 #229 的设计 Agent 先核对产品呈现。截图都由同一组合成响应在 2026-09-29 的本地 Edge 中生成；它们不是最终真实招生响应或检查点 2 的验收证据。旧版取自设计合并提交 `c4e6d0691c65187a3fec9b4e8af9f4dec804ad00` 的 `advanced.html/app.js/app.css/overview.js`，新版取自本 PR 的四步页面。没有启动真实服务、读取 391 runtime、调用模型或生成真实报告。

## 实际复用映射

| 已有组件／入口 | 实际复用方式 | 必要差异 | 放弃复用的具体理由 |
| --- | --- | --- | --- |
| `advanced.html` | 直接作为 `/app` 与 `/app/advanced` 的页头、四步导航、选择表单、主栏个人情况、行动摘要、证据弹层和高级工具 | 第二步和第四步加同一参考报告动作；第三步按能力显示原全部东科大字段或东大在职条件 | 没有放弃旧四步页面；UI-01 主页面结构与用户要求的四步顺序不同，不作为新主页面。 |
| `app.js` 的 `renderRequirements`、`renderKeyDates`、`renderRequirementCard` | 原函数继续呈现东科大申请概览、必着时间线、材料卡片、主栏 CTA 与原文入口 | 材料区展示所有已审核材料及官方适用性；东大已验收证据映射为旧卡片输入，日期明确“当前资料尚未覆盖日期” | 东大现有切片没有日期数据，不能复用东科大的日期值或假设。 |
| `app.js` 的 `renderComparison`、`renderPriorityActions`、`applyReadinessFilter` | 原函数继续处理东科大行动摘要、数量、分组、筛选与会话内勾选 | 东大在同一第四步只呈现三主题条件结果，隐藏完整准备统计与筛选 | 东大没有完整准备规则；沿用东科大全量缺项统计会夸大覆盖。 |
| 原 `advanced.html` 第三步个人字段 | 东科大全部原有字段、帮助文案和旧详细报告输入继续保留 | 按能力显示东大现有两项在职条件输入 | 东大没有经审核的东科大式完整个人字段目录，不能复制那些字段作为东大判断条件。 |
| `app.css` 与 `overview.js` | 继续提供页面宽度、色彩、响应式布局、概览指标和个人情况入口 | 补报告弹层、次级动作、东大两项条件的样式；原日期和材料权重保持 | 没有放弃旧样式与概览组件。 |
| UI-01 `unified-core.mjs` 报告适配 | 复用能力目录、双身份范围、证据绑定、基础／个人展示导出及 GSFS byte-bound 报告验证 | 原学校选择控件只建立页面选项投影；报告进入四步页面的同一预览和复制弹层 | 旧详细报告 API 的权威契约不同，不能作为东大的报告，也不能把东大切片伪装成旧文档 ID。 |
| 旧版截图样例与现有浏览器测试 | 旧版截图取自设计合并 head 的原四步文件；保留旧功能测试，新的合成 Edge 流程在 `tests/test_ui02_browser.py` 检查同场景和能力边界 | 新增同场景旧／新桌面、手机截图及两校合成流程；历史截图测试用冻结的旧 `app.js` 身份核对 | UI-01 主页面测试仍检验旧 UI-01 适配器，不能代替恢复后四步页面的可见路径与重点核对。 |
