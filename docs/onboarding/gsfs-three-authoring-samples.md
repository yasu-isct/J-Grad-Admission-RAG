## 为什么这些结论成立

1. **志愿调查表**：追加提交物表物理p.1左侧上传栏，问卷所在行标注“全员”；专攻案内物理p.28（印刷26）说明必须用一般选拔表单生成PDF，再上传。表头适用于本行，不能误读右侧空白的“专攻指定方法”栏。
2. **在职学习计划书**：专攻案内p.28的E06给出两个在职条件；追加提交物表p.1的E08重申条件并给出PDF上传。E07虽在同一页，但涉及入学手续时的另一份单位承诺书，不与出愿阶段合并。
3. **英语成绩单**：共通募集要项p.6的E01要求查专攻；专攻案内p.28的E02明确无需提交；追加表p.1的E03仅引用送分方法。这是共通文件明确委托专攻说明，不是程序一律让“专攻文件覆盖共通文件”。

新问卷片段编号为DRAFT-Q1/Q2，不冒充现有已导入Fact；E01/E02/E03/E06/E07/E08引用既有记录，未改旧资料、信任指纹或规则。

## 字段怎么保存、哪些可以复用

| 信息 | 本样本字段 | 复用与限制 |
|---|---|---|
| 学校、专攻、年度、路线、入学批次 | 顶层target和source_set_id | 复用现有精确目标；同名材料不跨目标套用。 |
| 一条可以核对的事实 | claims中的field/value/evidence_refs | 普通材料直接展示；没有依据的截止日期、模板、资格不补造。 |
| 原文定位 | source_id、PDF SHA、物理页、片段ID | 使用既有PDF；印刷页另列。新问卷需后续独立审核和受控导入，不伪造KB/Fact ID。 |
| 个人条件 | condition及profile_fields | 在职条件直接复用现有两个字段、ALL组合和三值计算。 |
| 文件/条款关系 | relations | 区分补充、委托、仅供参考；这里是设计映射，不另建图数据库或新规则引擎。 |
| 给老师的中文说明 | reader | 文案和规则分开修改；“已准备”是个人自报，不从“官方要求提交”推出。 |
| 没有核验的内容 | unknowns | 明示未知，保留原文供后续新问题检索；不把三张摘要当完整知识库。 |

## 这次能得出的架构结论

三类资料能够用同一份“身份、事实、条件、关系、原文、中文说明”整理模板表达，现有条件计算可复用；不要仅保存中文报告。稳定字段支撑比较与筛选，阶段和条件支撑个人待办，原文和依赖关系支撑年度变更审核及新问题检索。

但这还不是“新架构比旧架构更快”的实验证据：同一个设计Agent看过已有审核成果，两个样本直接复用旧题；没有盲测、独立验收或可比较的开发计时。格式更整齐不等于扩校更快，也不意味着已实现通用导入器。

当前真实接入缺口：问卷不在现有三主题运行报告中，需新增审核片段并复用现有导入/报告边界；通用主题映射仍要设计。现有快照和信任锚不能自动扩展；将来只发布新版本并保留旧版，不覆盖391/334或既有东大候选。向量索引属于后续检索需求，制作这些样本不要求重建索引。
