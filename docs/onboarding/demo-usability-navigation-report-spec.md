Issue [#247](https://github.com/yasu-isct/J-Grad-Admission-RAG/issues/247)。状态：设计文档合并后唯一 Ready。属于 M17 演示准备，开发责任方 M17 Main，设计独立验收。
基线 `29a91ac9280349300c0d1890f48cf9e4244cd68c`；从包含本 Spec 的最新 main 开始。
[完整方针](demo-usability-development-plan.md)；[回滚点](../checkpoints/demo-before-usability-20260930.md)。

## 背景及用户可见目标

用户反馈东科大报告按钮像假按钮，进入第二步后无法直观返回换学校。
报告已有真实实现；保存响应桌面/手机第二/第四步均能打开，故当前尚未复现具体故障。
本任务让报告成功/等待/失败清楚可见，学校随时可更换，切校后不残留旧学校结果。

## 范围

1. 先读现有 generateReferenceReport / renderReferenceReport / legacyReport、按钮启用逻辑和 edit-target，
   核对当前运行版本与保存回放；记录定位结论，不把用户反馈直接当成“需重新开发报告”。
   覆盖第二步无个人信息、第四步已有对照、个人信息编辑后未重算、慢响应、接口失败与目标切换。
   未能重现原故障须如实写明，能证明的改进与未确认原因分开，不以“我这里正常”关闭用户问题。
2. 第二/第四步的报告按钮立即显示“正在整理…”等反馈，生成成功打开既有报告窗并聚焦；失败在触发按钮附近提示和提供明确重试方式，原输入保留。
   禁用/未就绪时提供原因；审核现有早退路径，避免无提示结束。重复点击不产生并发请求；过期响应不得打开旧目标报告。
   复用现有报告渲染、选题和复制，不新增报告后端或所谓 AI 报告服务。
3. 原四步页顶部显示当前学校/专业及明确“更换学校”按钮，从第二至第四步均易找到，手机亦然。
   返回第一步复用既有 edit-target/activateStep；只是打开选择不立即丢弃输入，实际更改学校/身份后执行现有失效清理。
   给出简短说明“更换后将清除当前查询结果”。不使用 window.location.reload；不新建首页路由。
   保留目前个人信息是否保留的既有规则；不得悄悄将不兼容学校字段应用到新目标。
4. 变更实际身份后清除旧基础要求、个人对照、报告、问答和来源窗口，取消或忽略迟到响应；
   关闭关系/原文窗并安全恢复焦点。此动作不清后台语料和索引。

## 非目标和设计约束

不实施 B 的全页字体/文案/材料解释/问答重新排版；仅本操作所需按钮文案属于范围。
不修改生产 Schema、招生规则、材料义务、检索/生成行为、M9 指纹或受保护基线；不合并暂停的 #236。
保留两校四步、#239 可选主题报告和 #245 关系窗口，无新框架、专校分支、资产复制或重建。
不在8003的 outputs/design-report02 开发，不切换/重置运行目录；选择确认空闲的独立开发工作区。

## 验收与必须交付的证据

- 定位说明：目标身份、页面步骤、按钮启用/事件/异常路径，区分确认故障、可能原因及未复现部分。
- 桌面1440/手机390：从原两校四步页进入，完成东科大第二步无个人信息报告、第四步个人结果报告；
  选题预览/复制一致，材料状态保持，日期单选不带材料结论。
- 报告等待/失败/重试及输入变化使用受控延迟/失败的保存响应回放，核对反馈就近可见、不会假成功或卡死。
  这些标为回放，不伪装真实服务故障。复用现有浏览器/投影测试，不新增模仿实现的测试。
- 在第二和第四步使用“更换学校”：无需刷新返回选择，ISCT→GSFS→ISCT 数据隔离，
  旧报告/问答/弹窗不再可见，旧响应不能污染新目标；原文窗口返回定位保持。
- 提供前后各一组代表桌面/手机截图、实际步骤和点击结果，避免大量重复截图。
- 必要最终真实闭环仅用既有资产；记录运行 head、请求计数及保护资产前后哈希。重放素材注明来源。
  无需为了证明按钮点通调用模型；问答清理用保存回答。
- 精确 head 现有 CI 和定向检查通过。设计独立审查功能与真实/回放证据后才能合并，不只看测试数量。

## 失败、回滚与交接

状态验证失败时保留输入并提示，旧结果不当成新结果。未解决误导/串校/点击无反馈问题不得放行。
回滚只撤销本任务代码，按固定标签恢复独立预览；不 reset 共享工作区或恢复覆盖数据。

一个 Issue 对应原 PR，更新同一交接记录：角色、Ready/In progress/Awaiting review/Changes requested/Accepted、
branch/head、已验证/未验证内容、累计预算、下一责任方。无需每项小修新增 Issue/PR。
验收合并后设计再发布 B 的实施 Spec；开发不得自动进入后续字体/文案/材料扩展工作。
