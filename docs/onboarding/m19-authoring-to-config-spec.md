## A→B→C→D：内部连续推进

### A. 列清人工输入与机械派生

提交“字段—维护位置—生成去向—仍需语义审核”表。复用 `reviewed_source_evidence`、`reviewed_fragment_import`、`reasoning/material_conditions`、`reasoning/material_slice_report`、`service/reference_workspace`、M18生成器和现有关系/报告UI。说明每处仍需人工维护的原因；本包不能交付成把重复手写从JS搬到多个JSON。

### B. 有限配置生成器，不增设执行引擎

新增或扩展一个开发期入口，支持generate/check/preview-config。允许少量CLI入口；复用现有模块，不重复实现PDF审核、候选发布、规则判断或报告组装。输出包括导入配置、绑定旧/新五主题的policy/plan、逐字段来源表、manifest、显式预览配置和M18展示数据；新输出可独立版本化，旧输入只读。

生成顺序：检查外部设计批准和输入hash → 从seed与既有文档身份机械形成import config → 现有纯mapper形成新候选预期/lineage → 从lineage重新绑定所有受影响来源 → 生成policy/plan及展示 → 完整loader审核 → 必要时显式发布唯一新候选并启动隔离预览。

需要明确区分两种权限：计算输出hash和开发用trust文件是机械绑定；批准新来源/中文解释/逻辑是设计工作。工具仅在外部批准文件匹配精确输入时生成本包隔离开发配置；不得自行更新批准hash、从自己的输出推导“已审核”，或写入旧trust。生成的所有新trust必须在最终PR独立复核后才视为已验收。生产启用始终不是生成器的副作用。

现有四主题允许使用已审v2 policy/plan为语义基底，按record/fragment ID从新lineage重绑hash和身份；旧条件、效果、例外、文案、阶段和关系必须逐字段保持。不对JSON做全局字符串替换。输出差异表分别列“来源/版本绑定变化”和“唯一新增调查表语义”，禁止旧业务含义悄然漂移。

小论文旧authoring保留原文件和原seed引用；如新五主题展示需要新seed/snapshot，生成层可在验证E09/E10全部内容及旧作者hash不变后产生显式适配结果，并保留原作者来源及新版本绑定映射。不得直接改原作者文件，或把旧seed hash假装成新seed。M18旧生成命令和旧输出只读check应仍可执行。

两个有指南的真实材料共用同一通用展示循环；旧三个无指南主题不补写新解释。允许扩展M18生成器支持多个作者条目，但不得按“调查表/小论文”写专用生成分支。学校/topic ID只能作为配置数据或关联键，不作为if分支决定招生结论。

### C. 一项真实接入，保留三种版本

新增唯一不可变v3审核片段候选，原v1/v2原路径只读；以新entry/config显式启用。实际五主题能查询、查看关系/原文、记录两个材料各自的三态自报并生成报告。旧配置仍加载旧3/4主题，新生成模块不得导致旧v2指南消失；可保留旧静态模块并由通用聚合器按snapshot选择，或提供确定性的多条目目录。不要手抄旧模块或改写旧生成产物来维持兼容。旧目录和新目录同时被引用时，每个完整身份只命中一个条目，重复身份拒绝。

同一页面不并列三个同名目标供用户猜版本，预览配置明确选定其一。沿用两校四步主页面、折叠指南和依据窗口；新材料随报告主题选择而正确包含/排除。换学校、换目标或失效结果清空两项个人记录和旧报告。官方要求与个人已准备保持分离。
