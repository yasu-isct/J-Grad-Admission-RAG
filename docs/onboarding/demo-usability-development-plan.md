## 用户目标与核验结论

使用者应该很快看懂：选的是哪所学校、需要什么材料、哪些已准备/待准备/尚未填写，以及下一步做什么。
报告要能带走，问答要易读；技术状态和重复说明不应占据正文。

- 字体：app.css 大量 700/800 字重分布在标题、正文提示、标签，缺少稳定层级；中日文字体回退需实机检查。
- 文案：app.js/advanced.html 直接展示“低保证参考回答”“系统对照状态”“判断边界”等内部术语。
- 材料：demo_requirements.py 的多项材料共用相同 explanation/next_action；app.js 又逐字段重复展示。
- 问答：loadGenerationStatus 直接显示后台 provider label。前台无需展示供应商/型号，配置与诊断仍留后台。
- 报告：generateReferenceReport 和 legacyReport 已存在。2026-09-30 保存真实响应回放在 1440/390、第二/第四步均能打开报告；这不是用户实际失败状态的复现，不能声称问题已解决，也不能据此重写报告。
- 换学校：已有 edit-target 返回第一步，但只叫“修改”，入口不明显。复用其状态流增加明确入口。

当前 main 不含暂停的 QA #236；之前 QA20 报告来自该 Draft。不能把换成在线 provider 描述为恢复了 Draft 全部改进，
也不能为本轮展示需求暗中合并、cherry-pick 或恢复 QA 行为修复。

### B：统一阅读体验（#250，本设计合并后唯一 Ready）

[完整实施规格](demo-readability-spec.md)。

一份复用原四步页面的代表场景先对照检查，再应用到其余状态，不新增独立样板产品或框架。
代表场景必须包含东科大已准备/待准备/未知材料、在线回答、报告，以及东大部分资料说明和依据入口。

1. 字体：复用当前 CSS 变量，建立统一字号/字重。建议正文 16px/400、辅助说明 13–14px/400、卡片标题 18px/600、分区标题 22px/600；正文行高约 1.6。根据现有布局调整，无需安装/下载字体。重点日期/动作少量加粗，禁止整段说明粗体。按钮和中日文沿用一致字体栈，1440/390 验证。
2. 文案：逐处建立旧文案→新文案→使用场景映射，避免仅批量替换词语。删除“低保证”成功提示，回答完成无需再解释技术等级。“系统对照状态”在材料处改为准备状态；“判断边界”只在确有具体事项时改为“需要确认”。范围说明集中一处：说明已整理内容和未覆盖部分，不重复冗长声明、不把部分材料称为完整清单。
3. 材料：中文易懂名为主，保留日文正式名用于查找官方表格。复用稳定 material code 和现有事实/规则绑定，在共享展示映射集中维护名称及解释，页面、个人对照和报告复用。每项说明“是什么”，实际有依据才补“如何取得/填写”。不得凭常识编写提交方式、有效期、原件要求或跨校适用性；通用释义与官方要求明确区分。逐项列来源映射供设计审核。
4. 清单：默认一行或紧凑条目显示名称、简短说明、准备状态、具体下一步；只对特殊条件展开。已准备是用户自报，未知不是缺材料。资格/成绩判断与材料准备分开，不把所有非通过状态统称“缺材料”；不再给每件材料重复学历提示。
5. 问答：名称为“智能问答”，不显示 DeepSeek/型号、RAG、reference_only 等字段。正文按段落/列表呈现，保持安全 DOM 渲染，不使用未净化 HTML。回答下方默认不铺来源/检索明细；主页面材料原文入口与后台引用校验保留。实质缺失条件、未覆盖问题和在线失败不能隐藏；失败明确显示，不能把离线原文标为 AI 回答。不改检索、提示词、provider、cache、回答语义或暂停的 QA 修复。
6. 报告：跟随同一材料说明和措辞映射，不新建模板引擎。保持选题、预览/复制一致、仅日期不出现材料结论、无证据链正文。

材料示意（开发时逐项核对，不直接当学校规定）：

> **入学申请表** · 入学志願票  
> 填写本次入学申请信息的表格。  
> **待准备** · 按募集要项说明填写。  
> 查看填写要求

准备信息未知时显示“尚未填写准备情况”；有明确未准备输入才归入待准备。

## 验收方式与协作

功能测试通过只是一个条件，还要按普通使用者从选校走到报告看一次。先列场景和期望呈现，再实现。
同一轮集中给出问题；提交修正后只验证变化和直接关联场景，不重复已完成实验，不把新的个人审美偏好当阻塞。
错误材料状态、跨学校结果混用、按钮无响应、原文错绑属于阻塞；不影响阅读的间距微调记录待办。
不设新增测试数量目标、不手工重复全仓测试；运行现有 CI 和改动相关验证。真实服务集中到必要最终闭环；
已保存响应可核验的文案/布局/交互优先回放。模型调用本轮 0，在线正文展示使用历史脱敏回答。
A、B 各自完整 Spec 控制其预算，不能借用 QA20 剩余额度。用户手动在线试用与开发验收分开记账。

两步完成后停止功能扩展，准备演示脚本、报告样张和私塾汇报材料。
