# 設計判断の記録（ADR）の読み方

このフォルダには 17 件の ADR（Architecture Decision Record：ある技術判断を、当時の状況・決めたこと・理由・影響の順で短く残す文書）があります。番号は作成順で、重要度の順ではありません。読む人のために、三つに分けて案内します。ファイルは移動していません。

## 1. プロジェクトの方針を決めた ADR（最初に読む 3 件）

この 3 件が、J-Grad の設計の骨格です。ほかの ADR はすべて、この 3 件の範囲の中で決めています。

| ADR | 決めたこと | ひと言で |
| --- | --- | --- |
| [0001](0001-derived-vector-index-contract.md) | ベクトル索引は知識ベース（`document_kb.json`）から導出した成果物であり、独立した事実の置き場にしない | 事実は一か所、索引は作り直せる |
| [0005](0005-grounded-generation-citation-boundary.md) | LLM はサーバーが選んだ根拠にだけ、不透明な番号で引用できる。番号を資料名とページに戻すのはサーバー | モデルは根拠を「使える」が「作れない」 |
| [0010](0010-reviewed-source-evidence.md) | 新しい学校の知識ベースを作る前に、人がレビューした原文の抜粋と関係から始める | 資料間の関係は人が確認してから使う |

## 2. 方向を変えた・撤回した記録（4 件）

うまくいかなかったことと、そのとき何をやめたかの記録です。面接や振り返りで参照するのは主にこの 4 件です。

| ADR | 何が起きたか | 決めたこと |
| --- | --- | --- |
| [0006](0006-validated-natural-language-and-exact-cache.md) | 自然言語回答の検証層を増やし続けた結果、正しい言い換えが弾かれ、人が審査できなくなった | 検証で通った言い回しだけ保持し、同じ質問の成功応答はそのまま再利用する。意味検証器を自作する方向はやめた |
| [0007](0007-typed-consolidated-answer-obligations.md) | 回答を型付きの命題に分解して全件照合する義務を課した | 製品の参考アシスタントについては後に置き換え（上の 0006 と M10-08 を参照） |
| [0009](0009-mineru-4.0.7-pilot-fallback.md) | 新しい PDF パーサー MinerU の比較試験が、予算超過と実行世代の混在で成立しなくなった | 結果を良く見せるための再実行はせず、不採用として凍結。検証できなかった項目を明記 |
| [0011](0011-explicit-build-profiles-and-reviewed-lineage.md) | 旧い知識構築コードに最初の学校の固有知識（ページ番号・年度・学院名）が埋め込まれていて、空入力からも 25 件の実体が生成された | 旧コードを `legacy-isct-v1` として隔離。新しい学校はレビュー済みの抜粋と系譜からしか入れない |

## この構成について

プロジェクトの規模（2 校・数十人の試用）に対して ADR の数は多めです。振り返ると、1 と 2 の 7 件が ADR として残す価値のある判断で、3 の 10 件は Issue や PR の説明で足りた内容です。次のプロジェクトでは、「後で蒸し返したくない判断」だけを ADR にします。
